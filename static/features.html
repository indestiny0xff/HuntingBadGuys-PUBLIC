04 File Analysis
EFA - Static analysis of every fetched file

EFA (Extracted File Analysis) downloads and inspects root files, crawled files and the domain's main page HTML - detecting file types, calculating entropy, extracting printable strings and reading magic bytes without execution.

TYPE
File type detection
Magic byte identification covers PE/EXE, ELF, PDF, ZIP/JAR/APK, Office (DOCX/XLSX/PPTX), HTML, JavaScript, PHP, Python, shell scripts, config files, binary blobs and more - independent of the server's Content-Type header.
ENT
Entropy + packing detection
Shannon entropy computed over the full file body. Values above 7.2 bits/byte are labelled packed / encrypted - a strong indicator of UPX-packed malware, encrypted payloads or obfuscated scripts. Labelled low / medium / high / packed.
STR
Printable string extraction
Up to 500 printable strings (≥ 4 chars) extracted from binary and text files alike - exposing embedded URLs, C2 addresses, API endpoints, registry keys and debug paths left in compiled artefacts.
NEW
Main page HTML analysis
The domain's root HTML (up to 1 MB) is automatically added to every full EFA run - so single-file SPAs, React bundles and inline script tags are analysed for file type, entropy and strings without requiring a separate crawl result.
FILE
Per-file & case-level controls
Each file row in Root Files and Crawled Files has individual EFA buttons - rerun analysis on a single file at any time. The EFA button on each case sidebar entry runs analysis across the entire case in one shot.
Binary analysis pipeline - PE · ELF · APK · IPA
HVI
Hex View Inspector
Interactive hex dump with drag-to-select bytes. Mirrors highlights between hex and ASCII columns in real time. Smart clipboard: copies selection as hex string, raw bytes or escaped C literal. Large dumps render as native-selectable plain text for zero-lag scrolling.
DIE
Binary Detection (diec)
Runs Detect-It-Easy on every binary - identifies compiler, linker, packer, protector and overlay. Results are colour-coded by category (Compiler / Linker / Tool / Packer / Overlay). Catches UPX, MPRESS, Themida, NSIS and 300+ other signatures.
DDV
Disassembly + Decompile
radare2 + r2ghidra two-pane view. Left pane: annotated assembly with addresses, raw bytes and operands. Right pane: pseudo-C decompilation. Hover any function name to cross-highlight both panes. Click to scroll-mirror. Supports x86/x64, ARM, AArch64, MIPS and more.
APK
Android APK View
APKs are extracted and dissected without execution. Pure-Python binary AndroidManifest.xml parser surfaces package metadata, SDK versions and component lists. Dangerous permissions (SMS, camera, overlay, call log, fine location) are highlighted in amber. Native .so files are parsed as ELF and opened in DDV for disassembly. JADX decompiles all DEX bytecode to Java/Kotlin with a live class filter - no Java runtime config needed on the analyst side.
IPA
iOS IPA View
IPA archives are unpacked and the main Mach-O binary is located automatically via Info.plist CFBundleExecutable. Fat binary slices are resolved to the arm64 slice. Entitlements are extracted from the embedded XML plist - dangerous keys like com.apple.private.tcc.allow are flagged in red. Frameworks and dylib load commands are listed. DDV (r2ghidra) runs on the main binary for disassembly and pseudo-C decompilation.
Text file analysis - JS · HTML · PHP · Python · Config
NT
Network Traffic Analysis
For every text-based file (JavaScript, HTML, PHP, Python and more), EFA statically extracts all outbound network calls without execution - fetch(), XMLHttpRequest.open(), axios, jQuery AJAX, WebSocket connections, HTML form targets and PHP file_get_contents / cURL calls. Results are rendered in a DevTools-style request table with colour-coded method badges (GET · POST · DELETE …) and source-type labels. Hardcoded API base-URL constants and GraphQL operation names are extracted as separate groups.
BEACON
C2 Beacon Detection
setInterval and setTimeout callbacks that contain network calls (fetch, XMLHttpRequest, axios) are flagged as Beacon Patterns with the timer delay in milliseconds. This pinpoints keylogger heartbeats, credential-exfil loops and C2 check-in routines embedded in phishing-kit JavaScript - the exact patterns a browser's Network tab would expose at runtime, found statically without page execution.

08 Alerts & Monitoring
Get notified when something changes

Link an alert to a case, pick a schedule, and the platform emails you the moment new results appear. Every triggered alert is also cached directly in the app.

1
Create a case
Group your targets under a named case - e.g. "Campaign May 2026". Everything scanned into that case stays together and can be queried as a unit.
2
Scan your targets
Submit domains and IPs with the case selected. DNS, HTTP chains, hashes, screenshots, EFI IOCs and BGP data all land in that case's workspace immediately.
3
Set an alert
Pick the case, enter your email, set a recurring frequency (every 5 min → 24 h) or a fixed daily time (e.g. 08:00 UTC). Add an optional query filter to be notified only when specific conditions are met.
MAIL
Email notification
Each alert email lists every new result - target, kind, HTTP status and final URL - so you can act immediately without opening the app.
CRON
Flexible scheduling
Run every few minutes for active campaigns, or set a fixed daily time - e.g. a morning briefing at 08:00 UTC - for quieter monitoring.
CACHE
Cached in the app
Every triggered alert is saved in the Cached panel inside the app - case name, timestamp and a preview of the new results - so nothing is missed even if you don't check email.
DEDUP
No duplicate noise
Already-seen results are never re-notified. The alert only fires for results that are genuinely new since the last run.
